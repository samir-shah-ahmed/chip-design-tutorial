Simulation answers "what does the RTL do?" The FPGA flow answers "which LUTs, flip-flops, and wires on this part implement it?"

  1. Synthesis — Yosys synth_gowin turns Verilog into a netlist of the device's cells and writes JSON.
  2. Place and route — nextpnr-himbaechel, with the Apicula Gowin chip database, puts those cells on the part and routes them. The .cst file is how a port becomes a pin.
  3. Bitstream — gowin_pack (from Apicula) writes a .fs file.
  4. Program — openFPGALoader talks to the board's USB debugger.

The Tang Nano 9K open-source commands, with the part strings from the Apicula nextpnr guide, look like this:

yosys -p "read_verilog tick.v; synth_gowin -top tick -json tick.json"
nextpnr-himbaechel --json tick.json --write tick_pnr.json \
  --device GW1NR-LV9QN88PC6/I5 --vopt family=GW1N-9C --vopt cst=board.cst
gowin_pack -d GW1N-9C -o tick.fs tick_pnr.json
openFPGALoader -b tangnano9k tick.fs

-f on openFPGALoader is what published Tang Nano makefiles add when they want the image written to flash so it survives power-off. Check openFPGALoader --help for the flag in the version you installed. Programming SRAM is lost when the board loses power.

Gowin EDA does the same four jobs behind a GUI. The Sipeed blink tutorials walk through it: new project set to the device, add the Verilog, Synthesize, open FloorPlanner and save the CST, Place & Route, then Program, choosing SRAM or flash. Pins that share a configuration function (MODE, DONE, JTAG) need the dual-purpose-pin checkbox or place-and-route refuses them. That checkbox is described on the Tang Nano 4K blink page.
