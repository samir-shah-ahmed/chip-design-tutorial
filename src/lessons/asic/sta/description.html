Static timing analysis walks every path and subtracts delay from the clock period. It does not simulate vectors. A path that is never sensitized in your testbench can still fail STA, and a path that passes STA can still be functionally wrong.

  • Setup — data launched by one edge must arrive at the next flip-flop before the following edge, minus setup time. Slack is positive when it does.
  • Hold — data must not arrive so quickly that it corrupts the same edge that launched it. Hold is about clock skew and minimum delay, not about the clock period. Making the clock slower does not fix hold.
  • After routing, the delays come from extracted parasitics (SPEF in the OpenROAD flow), not from the RTL.

The usual RTL response to a setup failure is the same as on an FPGA: split the cloud with a register and accept the extra cycle of latency. Hold failures are usually fixed in CTS and by the router inserting delay cells, not by rewriting the adder.
