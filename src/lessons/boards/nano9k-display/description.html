The Tang Nano 9K brings both a parallel RGB LCD header and an HDMI connector out of the same family of pins. The Sipeed LCD constraint page and the official hdmi.cst in sipeed/TangNano-9K-example are the pin lists to copy. They share RGB/TMDS pairs on the schematic (the net names are of the form PIN75_RGB_R3/HDMI_D2_P), so a design that drives the LCD and HDMI at the same time has to respect that those pins are not independent.

LCD, from the Sipeed constraint page

The page spells the horizontal sync pin LCD_HYNC. That spelling is theirs. Polarity is not stated on that page; take it from the panel you plug in.

IO_LOC "LCD_CLK" 35;
IO_LOC "LCD_HYNC" 40;
IO_LOC "LCD_SYNC" 34;
IO_LOC "LCD_DEN" 33;
IO_LOC "XTAL_IN" 52;

The rest of the color bus is on that same page: blue on 41, 42, 51, 53, 54; green on 55, 56, 57, 68, 69, 70; red on 71 through 75.

HDMI, from the official example CST

IO_LOC "tmds_clk_p" 69,68;
IO_LOC "tmds_d_p[2]" 75,74;
IO_LOC "tmds_d_p[1]" 73,72;
IO_LOC "tmds_d_p[0]" 71,70;
IO_LOC "clk" 52;
IO_LOC "resetn" 4;

Those are differential pairs (P then N in Gowin's IO_LOC form). A real HDMI image needs a pixel clock from the rPLL, well above 27 MHz, and a TMDS encoder. This lesson does not pretend to be that encoder. It is the line counter you need before the encoder: a pixel index and a sync pulse. Build the full serializer from the Sipeed HDMI example once this counter behaves.

Exercise: Assert hsync while x < H_SYNC. The parameters are tiny so the simulator can see the pulse. A 640-wide line is the same module with different parameters, plus the porch counts from the video mode you chose.
